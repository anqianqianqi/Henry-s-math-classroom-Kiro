Four claims, checked against the schema. Then a sandbox: delete things, and watch what else goes with them under today's foreign keys versus the proposed ones.

The claims

HOLDS

An occurrence just means there is a class that day.

class_occurrences( occurrence_date, start_time, end_time, session_number, topic, status ∈ upcoming | completed | cancelled ). One row is one sitting, on one date.

HOLDS

It never means the class still exists.

Existence is classes.is_active and the row itself. Enrolment is class_members( class_id, user_id ) — keyed on the CLASS, never on an occurrence. A class with zero sessions still exists and still has every student in it.

HOLDS

A class can occur on several days a week.

There is no unique constraint on class_occurrences at all — not on (class_id, occurrence_date), not on anything. Several days a week is fine; so is twice in one day. generateOccurrences already loops over an array of slots.

INTENT ONLY

There is no need to backfill, and a session is independent of student work.

Backfilling: correct, nothing requires it. Independence: correct as a design, FALSE in the schema today. session_materials and homework_assignments both hang off occurrence_id ON DELETE CASCADE. Run the sandbox.
